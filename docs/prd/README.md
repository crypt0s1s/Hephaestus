# PRDs

Product Requirement Documents define the product outcome we are trying to build before implementation details are chosen.

Use a PRD when a capability needs clear user value, scope boundaries, acceptance criteria, milestones, and validation expectations.

PRDs are separate from ADRs and implementation plans:

- PRDs define what product capability should exist and why it matters.
- ADRs record durable architecture decisions and tradeoffs.
- Plans in `docs/plans/` describe how a specific accepted capability will be implemented.
